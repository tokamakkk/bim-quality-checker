# 演示 Workflow 脚本 —— BIM 质量检查器

> **用途**：≤3 分钟演示/讲解视频的拍摄脚本（也适用于现场演示）。
> **主线故事**（DESIGN.md §演示主线）：上传缺陷模型 → 检查出问题 → 3D 直观看到 → AI 问答 → AI 确认后修复 → 复检全绿 → 导出报告。
> 所有对话 Prompt 与预期响应均与代码实现逐字核对（`src/agent/__init__.py`、`prompts/`）。

---

## 0. 录制前准备

- [ ] 启动：`python src/app.py`，浏览器打开 <http://127.0.0.1:7860>
- [ ] 窗口调至 ≥ 1366×768（DESIGN §7.3 的验收分辨率），建议 1920×1080 全屏录制
- [ ] 决定 LLM 模式：**配 key 录**（`.env` 设 `DEEPSEEK_API_KEY`，问答由 DeepSeek 基于注入上下文生成，更有"AI 感"）或 **离线录**（无 key，响应完全确定、零网络风险）。两种模式 Prompt 完全相同，仅助手措辞不同——推荐先离线彩排掌握节奏，正式录再看网络情况
- [ ] 关掉微信/邮件等弹窗通知，保证录屏干净
- [ ] **重录重置方法**：界面上重新上传 `sample_data/bad_model.ifc` 即可（修复只写 `.work/` 工作副本，原文件从未被改动——重传即撤销，这本身就是演示点）
- [ ] 预先在第二个浏览器标签页打开 `report_sample.html`（报告展示环节直接切标签，省 10 秒）

## 2. 分幕脚本（完整版 3:00）

### 幕① 开场（0:00–0:10）

**画面**：浏览器已打开应用，标题「🏗️ BIM 质量检查器」。

**口播**：「这是为 HKU AI Agent Technical Test 做的 BIM 质量检查原型：上传 IFC 模型，运行两条合规检查，AI 助手可以解释问题、并在你确认后直接修好模型。」

### 幕② 上传与检查（0:10–0:45）

**操作**：
1. 左栏「① 上传 IFC 模型」选择 `sample_data/bad_model.ifc`（2 墙 + 4 门、含 5 处故意缺陷）
2. 口播时手指左栏「模型信息」：文件名、IFC 版本、构件总数 6、主要类型
3. 点击「运行检查」

**屏幕预期**：
- 右栏摘要条：**`✅ 11 通过 · ⚠️ 1 警告 · ❌ 4 违规（共 16 条判定）`**
- R1 折叠组 2 条问题：`（未命名）IfcWall R1a`（红）、`墙-02 IfcWall R1b`（黄）
- R2 折叠组 3 条问题：门-01 800mm、门-02 700mm、门-03 800mm（红），门-04 1000mm（绿）

**口播**：「两条规则、16 条判定，三级结论——绿通过、黄警告、红违规。4 个违规、1 个数据缺失。」

### 幕③ 结果呈现（0:45–1:05）

**操作**：
1. 中栏 3D 视图上指出红门与黄墙（模型按判定着色，颜色与右侧一致）
2. 切换「显示模式」→「仅显示违规」：只剩 4 个红黄构件 → 切回「全部显示」
3. 中栏下方构件卡片：搜索框输入「门」，展示过滤与展开属性（GlobalId / FireRating / FireExit 等）

**口播**：「每个构件的颜色就是它的判定结论；「仅显示违规」一键聚焦问题构件。卡片列表可以直接搜构件、展开看全部属性。」

### 幕④ AI 问答（1:05–1:15）

**操作**：点右下角「收起 / 展开」打开 AI 质量助手面板，输入：

**预期响应**（离线确定性；配 key 时为 DeepSeek 生成，语义相同）：

> 当前模型有 3 扇门宽度不足：门-01（800mm）、门-02（700mm）、门-03（800mm），均小于 900mm（GB50016）。

**口播**：「助手直接基于检查结果回答，还给出了规范依据。」

### 幕⑤ 修复闭环（1:15–2:15）—— 核心演示

**第 1 轮 · 门宽（建议 → 确认 → 函数调用 → 自动重检）**

输入：

**预期响应**：助手分析问题、给出方案并主动询问——

**预期响应**：真实函数调用 `set_door_width` → 自动 `rerun_check` → 汇报——

## 3. AI 质量助手完整 Prompt 清单

> 「预期响应」为**离线确定性模式**的逐字文案（代码中的兜底实现，保证可用）；配置 `DEEPSEEK_API_KEY` 时由 DeepSeek 基于注入的【IFC 模型信息】【生效的检查规则】【检查结果】上下文生成回答，语义一致、措辞可变，失败自动回退到以下文案。表中数字为 `bad_model.ifc`（16 条判定）的验收口径。

### 3.1 问答类（Capability A：只读，不改模型）

| Prompt | 触发机制 | 预期响应（离线确定性） |
|---|---|---|
| `哪些疏散门宽度不满足要求？` | 命中确定性问答（门/宽/窄） | 当前模型有 3 扇门宽度不足：门-01（800mm）、门-02（700mm）、门-03（800mm），均小于 900mm（GB50016）。 |
| `哪些构件没有名字？` | 命中确定性问答（名称+空/缺） | 当前模型有 1 个构件名称为空：IfcWall。 |
| `哪些构件缺少防火等级？` | 命中确定性问答（防火） | 当前模型有 1 个构件缺少 FireRating：墙-02（数据缺失，无法判定）。 |
| `这个模型有什么问题？` | 配 key 走 LLM；离线走帮助菜单 | LLM：按上下文逐条列 4 fail + 1 warn。离线：帮助菜单（见 3.5） |
| 任意其他问题 | 配 key 走 LLM（注入上下文）；离线兜底 | LLM 基于上下文回答；离线回退确定性/帮助菜单 |

### 3.2 咨询建议类（Capability B：进入「建议 → 询问 → 确认」闭环）

| Prompt | 预期响应（离线确定性，末尾均带询问句） |
|---|---|
| `疏散门宽度不足，如何解决？` | 发现 3 扇门宽度不足：门-01（800mm）、门-02（700mm）、门-03（800mm），均小于 900mm（GB50016）。建议统一改为 1000mm。**需要我帮您修复吗？** |
| `还有什么问题需要修复吗？` | 自动定位剩余问题类别（顺序：门 → 名称 → 防火）。修复门后：发现 1 个构件名称为空：IfcWall。建议按类型补全名字（如 墙-01 / 门-01）。**需要我帮您修复吗？** |
| `还有什么问题需要修复吗？`（名称已修） | 发现 1 个构件缺少 FireRating：墙-02。建议统一补上「2h」。**需要我帮您修复吗？** |
| `墙-02 缺少防火等级，怎么修？` | 单个修复方案（对象锁定墙-02）：建议补上「2h」。**需要我帮您修复吗？** |
| `帮我看看模型` / `有什么问题？` | 无关键词时按严重度自动定位（门 > 名称 > 防火）生成方案并询问 |

### 3.3 确认 / 拒绝（闭环内）

| Prompt | 行为 |
|---|---|
| `请修复` / `好的` / `好` / `行` / `可以` / `修复吧` / `OK` | 确认执行：LLM function calling（`set_door_width` / `set_property` / `rerun_check`）→ 自动重检 → 汇报新判定 + 剩余问题提示；LLM 失败自动回退确定性执行 |
| `暂时不执行` / `先不管` / `不用了` / `算了` | 放弃方案：好的，暂时不执行修复。您可以随时再次提出修复请求。 |
| 无待确认方案时说 `好的` | 引导：当前没有待执行的修复建议。请先告诉我您想修复什么，例如：「疏散门宽度不足，如何解决？」 |

### 3.4 直接修复指令（Capability B：立即执行，无需确认）

| Prompt | 工具 | 预期响应（离线确定性） |
|---|---|---|
| `将所有小于 900mm的门改成1000mm` | `set_door_width`（批量） | 已修复 3 扇门（宽度 < 900mm 的改为 1000mm，工作副本已保存，原文件未动）。重新检查完成：✅ 14 通过 · ⚠️ 1 警告 · ❌ 1 违规（共 16 条判定）仍剩 1 条违规（属性问题），可继续修复。 |
| `把空名称的构件都补上名字` | `set_property(Name)`（批量） | 已补上名称 1 个构件（写入工作副本，原文件未动）。重新检查完成：✅ 15 通过 · ⚠️ 1 警告 · ❌ 0 违规（共 16 条判定）无违规，仍剩 1 条警告（数据缺失）。 |
| `给缺少防火等级的构件补上防火等级` | `set_property(FireRating)`（批量，默认 2h） | 已补上防火等级 1 个构件（写入工作副本，原文件未动）。重新检查完成：✅ 16 通过 · ⚠️ 0 警告 · ❌ 0 违规（共 16 条判定）全部通过。 |
| `给缺少防火等级的构件补上防火等级 3h` | 同上（自定义值 3h） | 同上，值改为 3h |
| `把门-02 的宽度改成 950mm`（带具体构件名） | `set_door_width` / `set_property`（单个） | 仅修改指定构件并重检 |

> 护栏（代码内置，演示时可口头提一句）：门宽钳制在 600–3000 mm；`set_property` 白名单只有 Name / FireRating；全部写入 `.work/` 工作副本，原文件不动。

## 6. 注意事项

- **LLM 两种录法**：配 key 录更有说服力（问答/建议由 DeepSeek 生成），但响应措辞不可控、每次调用约 1–3 秒延迟；离线录响应逐字确定、零延迟零风险。**建议正式录前各彩排一遍，再按网络情况二选一**；Prompt 无需任何改动
- **聊天节奏**：助手回复后会有约 1 秒的自动重检与 3D 重着色，别急着发下一条
- **画面构图**：聊天面板位于右下角浮动，录屏时把右栏结果与聊天面板同时留在画面内——"确认后右栏变绿"的联动是全片最有说服力的镜头
- **口播与手速**：口播同步覆盖输入等待时间，别冷场；Prompt 都是短句，正常打字速度即可
